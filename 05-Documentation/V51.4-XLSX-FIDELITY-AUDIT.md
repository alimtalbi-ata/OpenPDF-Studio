# OpenPDF Studio V51.4 — Audit de fidélité PDF → Excel

**Auteur : Abdelhalim Talbi** — 24 octobre 2026. Évolution incrémentale de la version applicative 51.4.

## Objectif et architecture

Le mode de conversion PDF → Excel avec tableaux enrichis exécute désormais un audit de sécurité et de fidélité **avant** la publication atomique du classeur. Le fichier de sortie n'est pas publié si le contrôle échoue.

Pipeline : PDF source → extraction PyMuPDF → XLSX temporaire → vérification du ZIP et des contenus actifs → comparaison des cellules et fusions avec une seconde extraction → vérification SHA-256 → publication exclusive.

Le module `03-Sources/openpdf_xlsx_fidelity_v515.py` fournit aussi un contrôle autonome :

```bash
python 03-Sources/openpdf_xlsx_fidelity_v515.py --pdf source.pdf --xlsx resultat.xlsx --report rapport.json
```

Le rapport JSON contient uniquement des mesures, les tailles et les empreintes SHA-256. Il ne reproduit pas les valeurs des cellules. Le rapport existant n'est jamais écrasé.

## Contrôles

- Refus des archives XLSX corrompues, chemins dangereux, doublons, liens symboliques, macros, composants externes, ratios de décompression excessifs.
- Refus des formules Excel actives et des hyperliens dans toutes les feuilles, y compris `Texte PDF`.
- Comparaison exacte des cellules extraites, des fusions, de la provenance et de la structure des feuilles.
- Vérification SHA-256 du PDF et du XLSX avant et après audit.
- Rejet avant publication sur échec, nettoyage du fichier temporaire.

## Qualification

Campagne locale Linux du 24 octobre 2026 : **11 nouveaux tests PASS**, **8 régressions tableaux PASS**, **12 tests de prévalidation Office PASS**. Les tests utilisent de vrais PDF synthétiques générés à l'exécution. Les campagnes Windows GitHub Actions sont distinctes ; elles ne remplacent pas une qualification graphique humaine Windows.

**Limite importante :** le contrôle établit une parité exacte avec l'extraction de PyMuPDF, **pas** la fidélité sémantique du tableau détecté ni la fidélité visuelle du document. Les tableaux sans bordures, cellules fusionnées complexes et documents métier restent à qualifier.

## Livraison et suites

La branche de développement est empilée sur la PR de préservation des cellules fusionnées. `main` reste inchangée. Les binaires Windows de cette modification ne doivent être déclarés qualifiés qu'après réussite des jobs natifs sur le commit final.

Prochaine priorité : corpus métier annoté, métriques de précision/rappel des tableaux, fidélité des cellules fusionnées, mémoire/temps et qualification UI Windows réelle.
