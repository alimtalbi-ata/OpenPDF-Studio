# OpenPDF Studio V50.9 — Corpus de compression vérifié

**Auteur : Abdelhalim Talbi** · 23 octobre 2026

## Correction prioritaire
Le benchmark V50.4 pouvait annoncer une compression réussie sans la vérification indépendante de couverture RGB ni le contrôle alpha V50.8. Désormais **tous les profils** exécutent la validation intégrale RGB à échelle bornée, la vérification indépendante pages/pixels et le contrôle de transparence, y compris sans seuil de gain minimal. Les empreintes SHA-256 des sorties sont confrontées au reçu de compression.

Un candidat refusé est supprimé du répertoire privé du benchmark et comptabilisé comme `rejected`. Les fichiers sources ne sont pas modifiés. Les dossiers de sortie existants sont refusés.

## Mesures supplémentaires
Le rapport JSON conserve le schéma `openpdf.compression.benchmark.v50.4` pour compatibilité et ajoute `verification=v50.9-rgb-coverage-alpha-sha256`, `process_cpu_ms`, les reçus `quality.coverage` et `quality.alpha`, ainsi que `by_profile` : succès, absence de gain, rejets, octets économisés et réduction pondérée uniquement sur les sorties acceptées.

## Reproduction
```bash
python 03-Sources/openpdf_compression_benchmark_v504.py dossier/a.pdf dossier/b.pdf --output-dir /tmp/openpdf-v509-corpus --profiles standard,smaller_only --strict
python -m unittest discover -s 04-Tests-et-Qualification -p test_compression_corpus_fidelity_v509.py -v
python -m unittest discover -s 04-Tests-et-Qualification -p test_compression_benchmark_v504.py -v
```

## Qualification et limites
Tests sur **vrais PDF synthétiques** (texte, transparence, falsification des contrôles). Les rapports de tests CI et la qualification Windows native doivent être consultés séparément ; le passage de tests Python sous Windows n'est pas une validation humaine de l'interface. L'échelle de rendu bornée ne certifie ni PDF/A, ni impression, ni OCR, ni accessibilité, ni fidélité Office. Les mesures CPU dépendent de la machine et ne sont pas des SLA. Aucun échantillon client n'est inclus.
